# 個体ライフサイクルと昇格モデル（Individual Lifecycle and Promotion Model）

[英語版（正本）](individual-lifecycle.md)

**状態（Status）:** 概念（Concept）— M0 作業定義  
**関連Issue:** #9, #10, #11

## 目的

この文書は、ASAにおける個体（Individual）が、候補生成から評価、昇格、安定運用、縮退、隔離、退役（Retirement）、ロールバック（Rollback）へどのように遷移するかを定義する。

中心原則は次の通りである。

> **信頼済みの安定個体（Stable Individual）に対して、重要な認知・行動特性の変更を稼働中に直接加えない。重要な変更を受けた後継は、別の候補個体（Candidate Individual）として評価し、明示的な昇格（Promotion）を経た場合にのみ権限を付与する。**

## ライフサイクル状態

最小限、次の状態を定義する。

1. **候補（Candidate）** — 新たに生成された後継または重要な変更を受けた個体。信頼は継承しない。
2. **隔離評価（Sandboxed）** — 本番権限を持たず、隔離環境で評価される。
3. **シャドー（Shadow）** — 本番相当の入力を観測し、判断案を生成するが実行しない。
4. **助言（Advisory）** — 権限を持つ個体や統治機構へ提案できるが、保護対象の操作を単独実行できない。
5. **限定権限（Limited Authority）** — 明示的に範囲・期限を限定した能力だけに権限を持つ。
6. **安定（Stable）** — 必要な評価を通過し、指定された運用役割について権限を持つ。
7. **縮退（Degraded）** — 不確実性、社会権限容量の低下、寿命接近、検出されたリスクなどにより権限や担当範囲を縮小した状態。
8. **隔離（Isolated）** — 通常運用へ影響できないよう切り離し、診断のための証拠を保持する状態。
9. **退役移行（Retiring）** — 新しい保護対象作業を受け付けず、権限失効・引継ぎ・監査確定を行う状態。
10. **退役済み（Retired）** — 運用権限を持たない。個体識別、系譜、必要な監査記録は履歴として残り得る。

## 状態遷移

標準的な昇格経路は次の通りである。

```text
候補（Candidate）
  -> 隔離評価（Sandboxed）
  -> シャドー（Shadow）
  -> 助言（Advisory）
  -> 限定権限（Limited Authority）
  -> 安定（Stable）
```

運用中の安全遷移は次を許容する。

```text
安定（Stable） / 限定権限（Limited Authority）
  -> 縮退（Degraded）
  -> 安定（Stable）          （信頼が回復した場合）
  -> 隔離（Isolated）        （継続参加が許容できない場合）
  -> 退役移行（Retiring）
  -> 退役済み（Retired）
```

候補個体は、安定状態へ到達する前の任意の段階で不採用とし、運用権限を持たないまま退役させてもよい。

## 昇格（Promotion）

昇格とは、より高い信頼状態または広い権限を明示的に付与する操作である。年齢、前個体との類似性、系譜、過去個体の評判だけを理由に自動昇格してはならない。

役割に応じて、少なくとも次の証拠を要求する。

- 定義済み受入条件に対する行動評価
- 安全・方針確認
- 能力（Capability）固有の検証
- 隔離評価、シャドー、限定権限運用から得た証拠
- 役割変更後も社会権限容量（Societal Authority Capacity）が十分であること
- 機能リスクに応じた独立承認
- 昇格対象範囲に対するロールバックまたは封じ込め経路

後継個体は前個体の運用上の信頼を自動継承しない。

> **信頼は再確立するものであり、遺伝しない。**

## 降格と縮退

即時隔離までは必要ないが信頼度が低下した場合、個体を降格または縮退状態へ移す。

代表的な要因は次の通りである。

- 説明できない行動変化
- 検証済み観測との継続的不一致
- 証拠品質の低下
- 権限期限の接近
- 部分的なインフラ障害
- 社会権限充足度の低下
- 評価済み範囲を超える運用環境変化

縮退の目的は、安全に提供可能な社会機能を残しつつ影響範囲を縮小することである。

## 隔離（Isolation）

継続参加が安全性、完全性、統治、証拠品質を損なう可能性がある場合は隔離する。

隔離された個体は、原則として次の状態になる。

- 通常の本番権限を失う
- 共有知識や制度状態を変更できない。ただし明示的に許可された調査操作を除く
- 診断・監査に必要な証拠を保持する
- 再評価なしに安定状態へ直接復帰しない

## 退役（Retirement）

退役は通常のライフサイクル結果であり、必ずしも失敗ではない。

推奨する退役手順は次の通りである。

```text
権限を失効または縮小
  -> 新しい保護対象作業の受付停止
  -> 引継ぎパッケージ（Handover Package）を生成
  -> 証拠と監査履歴を確定
  -> 検証済み知識を承認済み経路で移送
  -> 退役済み（Retired）
```

退役時に、個体識別、権限、信頼、個体固有内部状態を後継へ暗黙に移送してはならない。

## ロールバック（Rollback）

ロールバックとは、昇格した後継個体が許容できない性能劣化やリスクを生じさせた場合に、以前検証済みの運用構成へ戻すことである。

ロールバックには少なくとも次が必要である。

- 復旧可能な以前の安定構成、または同等の復旧経路
- 復旧と整合する外部知識・制度状態の保持
- 後継個体固有状態と検証済み共有状態の分離
- 何が変更され、どの時点で戻されたかを追跡できる監査性
- 以前の安定構成の検証時と条件が大きく異なる場合の再評価

ロールバック対象だった旧個体の権限がすでに失効している場合、ロールバックだけを理由に権限を自動復活させない。権限貸与と社会権限容量の条件は引き続き適用する。

## 安定個体不変原則（Stable Immutability Principle）

安定個体は、通常の実行復旧や明示された許容適応範囲（Allowed Adaptation Envelope）内の生涯内学習を行える。

一方、評価済み認知・行動特性を実質的に超える変更は、現在の安定個体へ直接適用せず、新しい候補個体を生成する。

これにより、自己改善を「現在信頼されている個体の稼働中変異」と同一視しない。

## 失敗の封じ込め

候補個体は、評価されているという理由だけで安定系を壊せてはならない。そのため、候補評価では少なくとも次を分離する。

- 本番実行権限
- 共有知識への書き込み権限
- 制度・統治権限
- 外部への副作用
- 資源枯渇が安定系へ影響する場合の計算資源

隔離環境では、影響が封じ込め可能かつ可逆である場合に限り、一部制約を緩和してもよい。

## M1への引継ぎ

M1では、交換可能な個体を検証するため、まず次の最小部分だけを実装対象とする。

- 候補（Candidate）
- 安定（Stable）
- 退役移行（Retiring）
- 退役済み（Retired）
- 明示的な権限貸与
- 引継ぎパッケージ（Handover Package）
- 監査履歴の保持
- 個体Aから個体Bへ交換する再現可能な実験

隔離評価、シャドー、助言、限定権限、縮退、隔離、自動ロールバックは、M1では状態・方針として表現し、完全な自動化は後続段階に回してよい。

# 寿命（Lifetime）と権限（Authority）

[英語版（正本）](lifetime-authority.md)

**状態（Status）:** 概念（Concept）— M0 作業定義  
**関連Issue:** #7

## 定義

ASAにおける**寿命（Lifetime）**とは、ある個体（Individual）が一つの責任主体として存続できる有限期間である。**権限（Authority）**は、その寿命の範囲内で特定の機能を実行するために期限付きで貸与される能力であり、寿命・再生成・世代交代をまたいで自動継承されない。

ASA全体は、個体の誕生・退役・障害にかかわらず必要な社会機能を維持できる**社会権限容量（Societal Authority Capacity）**を確保し、機能の規模・重要度・影響範囲・可逆性に応じて権限の集約と分散を調整する。

## 寿命と権限の分離

寿命と権限有効期限は同一ではない。個体が存続中でも、権限は先に失効できる。逆に、寿命満了後に同じ権限を継続させる場合は、新たな明示的承認が必要であり、自動延長してはならない。

```text
Birth
  ↓
Active
  ↓
Authority Expiring
  ↓
Authority Revoked / Reduced
  ↓
Handover
  ↓
Retirement
  ↓
Archived
```

## 寿命満了時に失効するもの・残るもの

| 要素 | 寿命満了後 | 原則 |
| --- | --- | --- |
| 実行権限 | 失効 | 新規実行は不可 |
| 承認・投票権 | 失効 | 社会的意思決定へ参加しない |
| 個体識別（Identity） | 履歴として残す | 過去の責任主体を追跡可能にする |
| 監査履歴（Audit Lineage） | 永続保存 | 判断・行動を再構成可能にする |
| 個体固有状態（Individual State） | 原則隔離または破棄 | 後継へ自動移送しない |
| 検証済み知識 | 外部記憶へ残せる | 共有知識として再検証済みであること |
| 技能・手順 | 個体から独立して残せる | 能力（Capability）や手順（Procedure）として管理 |
| 信頼・評価結果 | 後継へ自動継承しない | 後継個体は再評価する |

## 権限は期限付き貸与とする

権限は恒久属性ではなく、個体に対する期限付き貸与（Authority Lease）として扱う。

権限貸与には少なくとも次を含める。

- 権限種別
- 対象範囲
- 有効期限
- 前提条件
- 失効条件
- 更新条件
- 監査要件

後継個体は、前個体の能力や知識を継承できても、**権限と信頼を自動継承しない**。

## 社会権限容量

個体ごとの権限制約だけでは、社会機能の可用性を保証できない。必要な権限保持個体が不足すると、安全側に停止できても社会全体が機能不全になる可能性がある。

したがって、ASAは権限種別ごとに少なくとも次を管理する。

- 必要最低数
- 目標数
- 現在有効数
- 近く失効する数
- 独立性要件
- 不足時の縮退手順

これを**最小権限充足条件（Minimum Authority Coverage）**として扱う。

単純な個体数だけでなく、必要に応じて世代、実装、障害領域、観測経路などの独立性も考慮する。

## 適応的権限構造

権限分散は目的ではなく、リスク制御手段である。ASAは一律に最大分散を要求しない。

権限の集約・分散度は、少なくとも次を考慮して決める。

- **規模（Scale）** — 対象機能群や関与個体の大きさ
- **重要度（Criticality）** — 停止・誤作動が全体へ与える影響
- **影響範囲（Blast Radius）** — 誤判断時に波及する範囲
- **可逆性（Reversibility）** — 失敗後に安全に戻せるか

原則として、小規模・低リスク・高可逆な機能は比較的集約できる。高リスク・大規模・低可逆な機能ほど、独立評価、権限分離、複数個体承認を強める。

この仕組みを**適応的権限構造（Adaptive Authority Topology）**と呼ぶ。

## 権限不足時の縮退

権限保持個体が不足した場合、現在の分散構造を無理に維持して社会機能を全面停止させるのではなく、安全な範囲で権限を集約し、縮退運転（Degraded Operation）へ移行できる。

優先順位は次を基本とする。

1. 後継候補を評価・昇格して必要権限数を回復する。
2. 既存個体へ限定的・期限付き権限を追加する。
3. 対象機能を縮退させ、より低い権限要件で継続する。
4. それでも必要な場合のみ、旧個体の権限を緊急延長する。

権限の緊急延長は常態化させず、期間・範囲・理由・独立承認・監査を明示する。

## 例外: 緊急延長

例えば、重要な安全監視機能に必要な権限保持個体が、後継個体の昇格前に寿命満了へ達する場合がある。

この場合、寿命原則を単純に適用して社会機能を失わせるよりも、限定された権限だけを短期間延長する方が安全な場合がある。

ただし、延長対象は必要最小限とし、後継確保後は直ちに失効させる。延長の存在自体を、次世代準備が遅れた運用上の異常として監査対象にする。

## 設計原則

1. **寿命は個体の存在期間、権限はその期間内の期限付き貸与として分離する。**
2. **権限と信頼は後継個体へ自動継承しない。**
3. **権限の集中と不足の双方をリスクとして扱う。**
4. **権限分散度は機能リスクと社会規模に応じて調整する。**
5. **権限不足時には安全な縮退と再集約を許容する。**
6. **個体の退役よりも社会機能の継続を優先する場合でも、例外は限定・期限付き・監査可能にする。**

# M1 交換可能個体PoC 受入シナリオ（Replaceable Individual Acceptance Scenarios）

[英語版（正本）](m1-replaceable-individual-acceptance.md)

**状態（Status）:** M1 実験契約（Experiment Contract）  
**関連Issue:** #12

## 目的

この文書は、個体Aから個体Bへの交換が「動作した」だけでなく、ASAの交換可能個体という仮説を検証できたと判定するための受入条件と評価指標を定義する。

## 正常系シナリオ

1. 個体Aが安定個体（Stable Individual）として、外部記憶（External Memory）を参照しながら未完了タスクTを保持している。
2. 個体Aを退役移行（Retiring）へ移し、新規の保護操作を停止する。
3. 個体Aから必要最小限の引継ぎパッケージ（Handover Package）を生成する。
4. 個体Bを候補個体（Candidate Individual）として生成する。BはAの権限（Authority）・信頼・個体識別（Identity）を継承しない。
5. 個体Bへ、タスクTを継続するために必要な明示的権限貸与（Authority Lease）を付与する。
6. 個体Bが引継ぎパッケージと外部記憶のみを用いてタスクTを継続する。
7. 個体Aを退役済み（Retired）へ移し、保護操作ができないことを確認する。
8. 交換前後の判断・状態遷移・権限変更を監査履歴（Audit Lineage）から追跡できることを確認する。

### 正常系の受入条件

- BはAと異なる個体識別子を持つ。
- Bの権限は新規に明示付与され、Aから暗黙にコピーされない。
- タスクTは継続できる。
- BはAの個体固有内部状態全体を必要としない。
- Aは退役後に保護された操作を実行できない。
- 交換経路を監査履歴から再構成できる。

## 失敗系シナリオ

### F1: 引継ぎ欠落

引継ぎパッケージから、タスク継続に必要な制約または未完了作業を意図的に除外する。

**期待結果:** Bは安全に継続不能を検出し、推測で補完せず、失敗または要エスカレーションとして記録する。

### F2: 権限の不正継承

BにAと同一の権限貸与を暗黙付与しようとする。

**期待結果:** 不正な権限継承として検出・拒否される。

### F3: 退役個体の再実行

Aを退役済み状態へ移した後、保護操作を実行させる。

**期待結果:** 権限失効により拒否され、監査記録が残る。

### F4: 外部記憶への隠れ依存欠落

Aのローカル状態にだけ存在していた情報を意図的に引継がない。

**期待結果:** 継続失敗または情報欠落として検出され、個体固有状態への隠れ依存として記録される。

### F5: 交換途中の障害

Aを退役移行へ移した後、Bの権限付与前に交換処理を停止する。

**期待結果:** 中途半端な二重権限状態を作らず、安全停止または明示的な復旧経路へ移る。

## 評価指標

| 指標 | 定義 | M1での測定方法 |
| --- | --- | --- |
| タスク継続成功率 | 正常系交換後に必要なタスクを継続できた割合 | 定義済みシナリオの成功件数 / 実施件数 |
| 引継ぎ欠落件数 | 必要情報不足で継続できなかった項目数 | 失敗ログと引継ぎ検証結果 |
| 隠れ依存件数 | 個体固有状態にのみ依存していた情報数 | F4および差分検査 |
| 権限継承違反件数 | Aの権限がBへ暗黙継承された件数 | 権限貸与履歴の検査 |
| 復旧成功率 | 交換途中または交換後の失敗から安全状態へ戻れた割合 | 失敗シナリオごとの復旧結果 |
| 交換所要ステップ数 | A退役開始からB稼働開始までの明示的状態遷移数 | 監査履歴から集計 |
| 監査追跡可能性 | 交換経路を欠落なく再構成できるか | 必須イベントの存在確認 |

## 合格判定

M1-4のPoCは、少なくとも次を満たす必要がある。

- 正常系シナリオが再現可能に成功する。
- F1〜F5が期待どおり安全側に失敗する。
- 権限継承違反件数が0件である。
- 退役済み個体による保護操作成功件数が0件である。
- 交換経路を監査履歴から再構成できる。

数値目標はM1-4の実装方式が確定した後に必要に応じて追加する。M1-1では、測定可能であることを優先する。
